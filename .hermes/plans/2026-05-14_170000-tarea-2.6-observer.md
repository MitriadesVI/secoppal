## Goal

Implementar `UniverseInsights` — un componente que analiza el universo completo
de resultados (no solo los 10 del sample) y produce estadísticas estructuradas
+ señales interpretadas que el narrator (2.7) usa para decir cosas
observacionalmente interesantes grounded en datos reales.

Ejemplo de output esperado al usuario:
> "Encontré 1.247 contratos de mantenimiento en Antioquia. El 60% son del INVÍAS.
> La mayoría son de 2025. Llama la atención uno de $2.300M cuando la mediana es $180M."

---

## Contexto / suposiciones

- `total_count` ya existe en el state (tarea 2.0).
- Los 10 rows del sample ya viven en `state["results"]`.
- Cuando `total_count <= 50`, los 10 rows son suficientes para calcular stats
  en memoria (sin queries adicionales).
- Cuando `total_count > 50`, el observer lanza queries SoQL de agregación
  en paralelo (ThreadPoolExecutor) para obtener distribución real del universo.
- El observer NO narra. Solo produce `UniverseInsights`. El narrator (2.7)
  es quien interpreta y genera texto.
- El observer es best-effort: si falla cualquier query individual, ese campo
  queda None. Si falla el conjunto, `universe_insights=None`.

## AJUSTE 2: Paralelización con ThreadPoolExecutor

Las 5 queries de agregación se ejecutan en paralelo. Latencia esperada:
max(queries) ≈ 800ms-1.5s en lugar de sum(queries) = 5-10s secuencial.

```python
from concurrent.futures import ThreadPoolExecutor, as_completed, TimeoutError

def _compute_from_aggregation(self, ...) -> UniverseInsights:
    query_fns = {
        "top_entities":    lambda: self._query_top_entities(...),
        "value_stats":     lambda: self._query_value_stats(...),
        "top_modalities":  lambda: self._query_top_modalities(...),
        "date_range":      lambda: self._query_date_range(...),
        "temporal_dist":   lambda: self._query_temporal_dist(...),
    }
    results = {k: None for k in query_fns}

    with ThreadPoolExecutor(max_workers=5) as executor:
        futures = {executor.submit(fn): name for name, fn in query_fns.items()}
        try:
            for future in as_completed(futures, timeout=5):
                name = futures[future]
                try:
                    results[name] = future.result(timeout=1)
                except Exception:
                    results[name] = None  # best-effort individual
        except TimeoutError:
            pass  # timeout global: usamos lo que llegó, el resto queda None
    # Nota: futures no cancelados siguen en background hasta que el HTTP
    # request de Socrata termine. Por eso cada aggregate() recibe timeout=4s
    # (menor que el global de 5s): el thread se libera limpio en ~4s en vez
    # de quedar colgado hasta el timeout default del cliente (30s).
    # Relevante cuando haya tráfico concurrente real.

    return self._build_insights(results, total_count, computed_from="aggregation")
```

## AJUSTE 3: Señales interpretadas en UniverseInsights

El narrator (2.7) recibe estas señales, no los datos crudos directamente.
Las reglas son determinísticas — el narrator NO deriva interpretaciones.

```python
@dataclass
class UniverseInsights:
    # Datos crudos
    total_count: int
    sample_size: int
    date_range: tuple[str, str] | None
    top_entities: list[tuple[str, int]]       # [(nombre, count), ...]
    value_stats: dict | None                  # {mean, median, min, max}
    top_modalities: list[tuple[str, int]]     # [(modalidad, count), ...]
    temporal_distribution: dict[int, int]     # {año: count}
    computed_from: str                        # "sample" | "aggregation"

    # Señales interpretadas (NUEVO — interface para el narrator)
    has_dominant_entity: bool          # True si top 1 entidad > 40% del total
    dominant_entity_name: str | None
    dominant_entity_pct: float | None

    has_temporal_concentration: bool   # True si un año tiene > 60%
    dominant_year: int | None
    dominant_year_pct: float | None

    has_value_outlier: bool            # True si max > 5x mediana
    outlier_value: float | None

    has_diverse_modalities: bool       # True si top modality < 50%
```

Umbrales fijos (no configurables en v1.2):
- Entidad dominante: > 40% del total_count
- Concentración temporal: > 60% en un solo año
- Outlier de valor: max > 5× mediana
- Diversidad de modalidades: top modality < 50%

Función helper `_derive_signals(raw_data, total_count) -> dict` que computa
los 8 campos booleanos/null. Pura, sin side effects, fácil de testear.

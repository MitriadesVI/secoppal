# M2A_GOLD r3b: entrada para el etiquetado ciego

Etiquetan dos etiquetadores (A y B), cada uno por separado y sin ver el trabajo del otro.

## Instrucciones

1. **Autoridad.** Hay dos, y sólo dos:
   - el contrato `docs/decisions/M2A_CONVERSATION_CONTRACT_V1.md` (en esta rama, con las enmiendas R3 y R3b);
   - el esquema `docs/audits/m2a_advisory_2026-10-01/02_gold_followups/kit_v2_2/SCHEMA_v2_1.md`.

   Donde difieran, manda el contrato (§0; el Anexo B dice cómo se lee el esquema). No consultes ningún otro documento,
   test ni archivo del repositorio, ni etiquetas de otros casos.
2. **Etiqueta.** Para cada caso de abajo, produce una etiqueta con la forma de `label_A` / `label_B` del esquema 2.1.
   - Copia tal cual: `gold_id`, `schema`, `slice`, `source_kind`, `input_kind`, `followup_text`, `followup_sha256` y
     `prior`.
   - Completa: `labeler` (`A` o `B`), `turn_kind`, `m2a_scope`, `ops`, `expected_disposition`, `disposition_reason`,
     `resulting_ir`, `effects`, `expected_echo`, `alternatives`, `ambiguity`, `confidence`, `gap_codes` y `notes`.
3. **Pendiente previa.** Si `prior.state` es `PENDING`, `prior.ir` es el marco de la pendiente (lo que ya estaba
   resuelto) y `prior.pending` es la pregunta abierta, con sus opciones.
4. **Varias lecturas.** Si un caso admite más de una lectura bajo el contrato, no la fuerces: márcala en `ambiguity` y
   `confidence` y explica en `notes` qué regla lleva a cada una.
5. **Normativo, no provisional.** Etiqueta lo que el contrato prescribe con las autoridades y capacidades que nombra
   disponibles. Un comportamiento provisional fail-closed mientras falta una dependencia declarada en §19 no es la
   etiqueta: el caso cuenta como rojo declarado hasta que la dependencia exista (§19, §20.2).
6. **Entrega.** Un JSONL, una etiqueta por línea, en la ruta que indique el orquestador. No modifiques el repositorio.
